# closet-cli

CLI-инструмент, который создаёт и поддерживает файлы/папки для одного или нескольких ИИ-агентов (Claude Code, Codex, ...) в проекте пользователя, устанавливая туда «плагины», скачанные с self-hosted `closet-registry`. По духу — как пакетный менеджер, только вместо пакетов npm ставятся `rules/`, `skills/`, `commands/`, `agents/`, `hooks/`, `mcp/`, `scripts/`.

## Установка

```bash
pnpm add -g @punkdevs/closet-cli
```

Требуется Node.js ≥ 22.

## Быстрый старт

```bash
# 1. Инициализировать окружение в текущем проекте
closet-cli init

# 2. Установить плагин (с автоматическим подтягиванием зависимостей)
closet-cli install gitflow

# 3. Обновить до последней версии
closet-cli update gitflow

# 4. Удалить
closet-cli remove gitflow
```

## Как раскладываются файлы

Каждый ИИ получает файлы там, где сам их читает; дублей нет. Claude Code не читает `.agents/`, поэтому его файлы пишутся сразу в `.claude/`. Codex читает `.agents/` сам, поэтому его файлы лежат прямо в `.agents/`. Ссылки (symlink/junction) и копии между папками не используются.

```
.claude/skills|rules|commands|agents   # файлы Claude Code (источник правды для Claude)
.agents/
  skills/<name>/SKILL.md               # Codex читает сам
  agents/<name>.toml                   # Codex читает сам
  hooks/…  scripts/…                   # только хранилище: на них ссылаются пути в настройках хуков
```

| | Claude Code | Codex |
|---|---|---|
| `skills` | `.claude/skills` | `.agents/skills` |
| `rules` | `.claude/rules` | пока не поддержано |
| `commands` | `.claude/commands` | нет аналога |
| `agents` | `.claude/agents/<name>.md` | `.agents/agents/<name>.toml` |
| `hooks`, `mcp` | merge в `.claude/settings.json`, `.mcp.json` | merge в `.codex/config.toml` |
| `scripts` | только `.agents/scripts` | только `.agents/scripts` |

Для Codex раскладка опирается на его документацию; на практике она не проверялась.

Правки вносите прямо в файлы под `.claude/` и `.agents/`. Для каждого файла в `closet-cli.json` хранится sha256 на момент записи: если файл изменили руками, `install`/`update` считают это конфликтом (спросят, пропустят или перезапишут — см. флаги `--force`/`--skip`).

Агент, который в админке реестра создан как «универсальный» (один текст, несколько целей), приходит в CLI уже готовыми файлами под каждый ИИ — CLI ничего не конвертирует сам.

## Команды

### `closet-cli init`

Интерактивный диалог: адрес реестра (`registry.host`), токен (скрытый ввод, опционально; сохраняется в персональный файл, не в `closet-cli.json`), какие ИИ включить (`Codex`/`Claude Code`) и нужно ли сгенерировать корневой `AGENTS.md`.

По выбранным ИИ создаёт в текущей директории:

- хранилище `.agents/{skills,rules,commands,agents,hooks,scripts}/`;
- Claude Code: `.claude/{skills,rules,commands,agents}/`, `.claude/settings.json`, `.claude/settings.local.json`, `.mcp.json`; добавляет `.claude/settings.local.json` в `.gitignore`;
- Codex: skills и agents читаются прямо из `.agents/skills` и `.agents/agents`.

Если подтверждено «сгенерировать `AGENTS.md`» — создаёт корневой `AGENTS.md` (общая конфигурация поведения для всех ИИ) и, для Claude Code, файл `CLAUDE.md` с единственной строкой `@AGENTS.md` (Claude Code подтягивает `AGENTS.md` через этот импорт; Codex читает `AGENTS.md` нативно, мост ему не нужен). Если не подтверждено — не создаёт ничего из этой группы. Повторный `init --force` никогда не перезаписывает уже существующие `AGENTS.md`/`CLAUDE.md` — только досоздаёт недостающий файл-мост для новых ИИ.

В конце всегда пишется `closet-cli.json` — файл состояния проекта (`registry.host`, `ai`, `plugins`). Токен в него не пишется.

Флаги для неинтерактивного запуска (CI, скрипты):

- `--force` — переинициализировать поверх существующего `.claude/`/`.codex/`/`closet-cli.json`.
- `-y, --yes` — не показывать промпты, использовать флаги/значения по умолчанию везде, где это возможно.
- `--host <url>` — адрес реестра.
- `--token <token>` — персональный токен реестра (`clt_…`); сохраняется в `closet-cli.local.json` (он добавляется в `.gitignore`), а не в коммитящийся `closet-cli.json`.
- `--ai <list>` — список ИИ через запятую, например `codex,claude-code`.
- `--agents-md` / `--no-agents-md` — сгенерировать `AGENTS.md`+мосты или пропустить эту группу без вопроса.
- `--layout <agents|legacy>` — раскладка файлов; по умолчанию `agents` (описана выше). `legacy` — прежняя раскладка без `.agents/`, оставлена для старых проектов (в `closet-cli.json` у них нет поля `layout`).

Любой из этих флагов пропускает соответствующий промпт даже без `--yes`. Без `--force` команда откажется работать, если `.claude/`, `.codex/` или `closet-cli.json` уже существуют. В неинтерактивном окружении (нет TTY) `--host` обязателен всегда, а `--ai`/`--agents-md`/`--no-agents-md` — обязательны, если не передан `--yes` (у него есть дефолты: оба ИИ, генерация `AGENTS.md`).

### `closet-cli install <slug>`

Устанавливает плагин и все его транзитивные зависимости. Файлы пишутся туда, где их читает каждый включённый ИИ (см. таблицу выше):

- файл с `ai: null` (общий) — пишется под КАЖДЫЙ включённый в проекте ИИ, у которого для этого компонента есть место;
- файл с конкретным `ai` — только под этот ИИ, и только если он включён в `closet-cli.json` (`ai.*`).

Компонент без аналога у конкретного ИИ (например, `commands` для Codex) — пропускается с уведомлением в выводе команды, не ошибкой. Файл с `ai`, который эта версия `closet-cli` не знает (реестр поддерживает более новые ИИ), тоже пропускается с предупреждением «обновите closet-cli» — установка не падает. Merge-компоненты (`mcp`/`hooks` для обоих ИИ) мёржатся в существующий `.mcp.json`/`.claude/settings.json`/`.codex/config.toml` по именованному слоту (`mergeKeyPath`), не трогая остальные ключи файла.

Если какой-то из файлов  уже существует на диске и отличается по содержимому (или merge-слот уже занят чужим значением):

- в интерактивном терминале — по каждому конфликту будет задан вопрос «Перезаписать?»;
- `--force` — перезаписать все конфликтующие файлы без вопросов;
- `--skip` — пропустить все конфликтующие файлы без вопросов;
- в неинтерактивном окружении (CI, пайпы) без `--force`/`--skip` команда завершится ошибкой со списком конфликтующих файлов.

`--force` и `--skip` взаимоисключающие. Плагин, который уже установлен, повторно `install` не ставится — команда укажет использовать `update`.

### `closet-cli update [name]`

Обновляет один плагин (`update <name>`) либо все установленные с `autoupdate: true` (`update --all`; `update <name>` обновляет независимо от `autoupdate`).

Плагин обновляется целиком, только если НИ ОДИН его ранее установленный файл  не был изменён вручную с момента установки. Если изменён хотя бы один файл — весь плагин пропускается с предупреждением. `--force` перезаписывает даже изменённые файлы.

### `closet-cli remove [name]`

Удаляет один установленный плагин (`remove <name>`) либо все (`remove --all`). Обычные файлы удаляются с учётом reference counting: если один и тот же файл на диске используется ещё каким-то оставшимся установленным плагином, он не удаляется. Пустые директории после удаления файла подчищаются. Merge-файлы (`.mcp.json` и т. п.) никогда не удаляются целиком — только свой именованный слот внутри них, остальные ключи не трогаются.

### `closet-cli sync`

Заново копирует файлы хранилища `.agents/` в папки ИИ по `closet-cli.json` для ИИ, у которых размещение — копия. Сейчас ни у Claude Code, ни у Codex такого размещения нет, поэтому команда почти ничего не делает; она оставлена для будущих ИИ. Синхронизация односторонняя; копии, изменённые руками, считаются конфликтом: `--force` перезаписывает их, `--skip` пропускает (без флагов — вопрос в интерактивном терминале). Работает только с раскладкой `agents`.

### `closet-cli list`

Без флагов — список установленных в проекте плагинов из локального `closet-cli.json`, без обращения к сети.

`closet-cli list --all` — все плагины, опубликованные в реестре.

### `closet-cli login`

Сохраняет персональный токен реестра (`clt_…`) в `closet-cli.local.json` в корне проекта (файл автоматически добавляется в конец `.gitignore`; права `0600` на POSIX). Токен проверяется живым запросом `GET /v1/auth/me` и сохраняется только при успехе. Сессионный токен админки (`cls_…`) отклоняется.

Флаги: `--host <url>` (по умолчанию из `closet-cli.json`), `--token <token>` (иначе — скрытый ввод).

Получить токен: админка реестра → «Аккаунт» → «Токен». Токен показывается один раз; перевыпуск отзывает старый.

### `closet-cli logout`

Удаляет сохранённый токен для реестра проекта (`--host <url>` — для другого реестра).

### `closet-cli whoami`

Показывает пользователя, роль и источник токена (проверка валидности токена).

### Где хранится токен

Приоритет источников:

1. переменная окружения `CLOSET_CLI_TOKEN` (CI, разовые запуски);
2. `closet-cli.local.json` в корне проекта, запись для `registry.host` (файл не коммитится);
3. устаревшее поле `registry.token` в `closet-cli.json` — работает с предупреждением.

Если токена нет нигде, `install`/`update`/`list --all` завершаются с подсказкой до сетевого запроса.

### Миграция со старого `registry.token`

Выполните `closet-cli login` и удалите поле `registry.token` из `closet-cli.json` (CLI сам файл не правит). Если файл с токеном уже коммитился, токен скомпрометирован: перевыпустите его в админке (старый отзовётся автоматически) — удаления из файла недостаточно, токен остаётся в истории git.
